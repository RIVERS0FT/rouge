# 实现说明 · v0.1

## 领域边界

`src/game` 不导入 React、Three.js、DOM、平台 SDK 或真实时钟。Engine 接收显式命令，按 0.05 秒固定步长推进。输入必须由 Engine 验证所有权、邻接、派出比例、军费、兵种配置和当前天赋候选。浏览器动画仅消费快照。

单人 `localSession → Worker → Engine`，每 100ms 发布视图快照。暂停与速度属于本地会话，不写入战争规则。LAN `React → POST 命令 / SSE 快照 → Node Engine`。服务器从随机席位 token 解析 actor，不信任客户端 actor 字段。房间成员最多四名；房主只能发开始命令，不能从客户端直接写入世界状态。

## 模拟与移动

省份是凸 Voronoi 多边形；共享一条具有长度的边才构成邻接。数据是架空测试大陆，不是已完成的真实行政地图。训练、战斗、占领、升级、天赋和 AI 都在模拟内执行。

流场使用反向 Dijkstra 累计代价，缓存键包含玩家通行权限、目标省份、拓扑版本。格点为 0.8 单位，130×78。海面和非法过境省份不可通过，禁止斜向穿越阻挡角点。部队共享流场，不为每兵团计算独立 A*。进入凸目标省份后允许接近守军的局部直线 steering，避免“到中心附近但永远射不到最后一名守军”的死锁。

这是**单网格共享流场原型**，不是完整分层分块流场。没有严格兵团碰撞、拥堵排队或桥梁容量；视觉编队偏移不参与模拟。下一阶段再引入扇区出口图、动态代价和局部避让，不能将目前实现称作已完成这些能力。

伤害在每步累计后统一应用，避免遍历顺序阻止濒死单位反击。空间桶减少战斗候选查询。经验和候选组使用状态内的 xorshift 随机序列；AI 决策同样消耗该序列。相同种子和命令序列在当前引擎版本下可重放，但未承诺跨 JS 引擎的竞技锁步一致性。

## 渲染

近远景共享坐标、相机焦点、省份和军队。地形 morph target 随缩放混合，政治填色向地形色过渡。近景开启树林、城镇和士兵表现。每个逻辑兵团用 3 个代表性模型实例显示；360 逻辑实体上限与 1,080 士兵显示实例不能混为一谈。模拟军队不因拉远消失而停止。

使用 Three.js 原生渲染循环，不为每个士兵创建 React 节点。每帧单位位置向快照插值。省份标签仅在名称、数量或归属改变时更新 CanvasTexture；所有几何、材质、标签纹理、监听器和渲染循环在卸载时释放。

当前为程序化占位资源，不是写实最终美术。三维按钮改变镜头层级，而不是加载第二套游戏地图。

## 存档

每个 localStorage 槽位保存带版本、地图 ID、时间、校验和及完整战局 JSON 的 envelope。校验和仅用于误损检测，不是安全签名。覆盖前备份上一份有效 envelope；主版本损坏时尝试备份。每次 setItem 原子写入，失败不会删除之前有效的主版本。

保存 RNG、生产、军队、升级、AI 状态、待选天赋、重抽次数、胜利计时；不保存 Three.js 对象或流场缓存。导入限制为 3MB，检查类型、范围、ID 唯一性与内容版本。浏览器配额有限，因此保留 JSON 导入/导出入口。没有云存档或旧版本自动迁移。

## LAN 安全边界

HTTP/SSE 使用随机 24 字节席位 token；每席位每秒限制 30 次接口请求；每席位最多一条活动快照连接；服务器限制请求体和缓冲区，默认最多 16 个房间。房间无连接且闲置 30 分钟后释放。只接受同源浏览器请求，不配置宽松 CORS。

不应部署到公网：没有 TLS、账号系统、跨网络 NAT 穿透、房间密码、完善的全局 IP 限流或 DDoS 防护。世界大部分信息公开，尚未实现迷雾。服务器对其他席位隐藏待选候选，但并非完整反作弊。服务器停止无迁移恢复。Steam/Epic 能力显式为 false。

## 验收与下一步

本地核心、兼容性与真实 HTTP LAN 测试共 16 项已通过。完整 TypeScript 检查、Vite 生产构建及单人浏览器端到端流程也已在 GitHub Actions 通过。另提供双独立浏览器上下文的 LAN 加入、各自升级与刷新重连测试。逐次运行结果及截图以 PR #1 的最新 CI 为准；浏览器模拟多客户端不等同于两台物理机验收。

CI 固定 Ubuntu 24.04，避免 ubuntu-latest 自动升级后与所锁定的 Playwright 不兼容。开发代理显式保留 Host，避免 Vite 字符串代理配置改写 Host 后触发 API 的同源保护；生产 LAN 服务不依赖开发代理。

下一阶段优先顺序：冻结实际安装 lockfile → 浏览器/两台物理机 LAN 验收 → 改进战斗目标与拥堵 → 导入真实 Admin1 小区域 → Electron 与 Steam/EOS SDK 技术验证 → 写实资源和规模压测。
