# v0.4 — 米勒地图不对称裁剪

## 范围与依据

保留标准球面米勒投影、0°中央经线、两轴相同赤道尺度。设置北界 74°N，以参考高度图的 16384:7232 宽高比推导南界 -58.64021112066765°。

这是项目采用的近似维多利亚式构图参数，不是 Paradox 公开确认的官方经纬裁剪值。公式依据 PROJ Miller 文档：<https://proj.org/en/stable/operations/projections/mill.html>。参考尺寸来自前一轮调查的公开 `heightmap.heightmap` 文件。不要把地理投影、裁剪框和相机倾角混为一谈。

```
X = [-1800, 1800]
Z = [-923.4389955662654, 665.6235044337346]
世界中心 = (0, -128.90774556626536)
宽高比 = 2.265486725663717
```

赤道保持 Z=0，不平移模拟坐标，不拉伸地理形状。`unproject` 仍能处理完整 ±90°米勒投影，裁剪只是独立的显示/玩法边界。

## 几何、标签和拾取

源经纬度 JSON 完全不改，4,596 个 ID 和顺序保持稳定。投影后的源环同样保留，运行时对其使用裁剪蒙版。

渲染先对含孔洞的多边形进行 Earcut 三角剖分，再逐三角形与裁剪矩形求交，重新三角化凸交集。不对任意凹多边形直接做单环裁剪，避免把分离区域错误连起来。边界线独立进行线段求交；不把越界顶点钳到边缘。

空间索引、拾取、搜索、标签、城镇和单位显示使用同一范围。保留部分可见省份；旧中心落在裁剪外时，用含孔洞的扫描线交集寻找内部中心，不使用可能落海的几何中心。

当前包共有 4,592 个可见且可玩要素。完全排除的四个源要素为 `ATA+00?`、`ATA+99?`、`GRL-2738`（Pituffik）、`NOR-901`（Svalbard）。这个数字仍是源数据行政要素数，不保证全部已归一为省级。

## 游戏规则

完全裁剪的省份保留 ID 占位，但不可占领、不生产、不收税、不进入胜利统计和 AI 目标；存档验证拒绝隐藏省份持有者和越界兵团。

相邻关系沿用源共享边界。至少一侧完整保留时保留原邻接，避免简化线段分段差异误删关系；两侧都受裁剪时只保留在框内有正长度的原共享边段。新切边不产生相邻关系，也不把点接触或隔海区域连接起来。

局部流场只生成框内陆地的有限代价格，移动每个采样点再次校验。仍只在省份主陆块上行军；没有用裁剪新增跨海、飞地或反经线军队运输。

## 横向循环与镜头

保留完整 360°经度。非全球视图使用共享几何的左右副本，相机平移跨反经线时回绕；拾取归一回同一行政区 ID。近景标签和单位使用最接近相机的显示副本，不复制模拟实体。

全球视图显示单幅地图，按裁剪后的中心和窗口比例适配，不再把赤道误当作裁剪后画面的中心。南北相机焦点限制在裁剪框内；允许视口外出现背景留白，以免倾斜镜头暴露极区地块。这里的横向循环是显示/交互功能，不代表实现跨反经线行军。

## 存档、联机和测试

应用 v0.4.0，战局 `version=4`、`map=earth-admin1-miller-crop-v1`。存档与重连凭证使用独立 crop 命名空间。旧墨卡托/完整米勒存档不删除、不覆盖、不自动导入；需要新建战役。同房间客户端必须使用相同地图版本。

`npm test` 验证投影范围、三角形与线段裁剪、孔洞、分离凹区域、可见中心、源邻接、流场边界、隐藏地区规则、存档隔离、联机与经度循环。浏览器验收检查实际绘制顶点范围，执行全图、极区搜索、江苏定位与反经线拖动，并保存真实截图。

未改变原有边界：没有真实 DEM、最终写实资源、Steam/EOS、海运、独立服务器反作弊、目标硬件帧率基准或双物理机验收。
