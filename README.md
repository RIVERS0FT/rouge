# ROUGE · 诸省之争

基于 React 与 Three.js 的领土地块征服策略游戏。

## 在线试玩

**[打开游戏：https://rivers0ft.github.io/rouge/](https://rivers0ft.github.io/rouge/)**

当前版本：**v0.5.0**。网站随 `main` 压缩合并提交先部署、再测试，实际发布源码以 `build-info.json` 和 Pages 工作流验收结果为准。

- 原始 4596 个 Natural Earth 完整行政区保留；程序化预处理合并直接生成1162个实际游戏地块，其中1158个可玩。选中、生产、驻军、占领与统计均按合并后地块，不再操作原始碎块。形状只部分近似 Victoria 3 州区，实测局限见 [形状审计](docs/GAMEPLAY_REGIONS_AUDIT.md)。
- 可以向非相邻地块下令，按独立地形陆海流场从单位实际位置行进，不把行政区中心串成路点。
- 每个预处理游戏地块固定容量12、生产速率1和一条生产队列。预处理与游戏内合并共用分组机制：前者锁定，后者可拆回完整基础地块，不增加资源。原图与合并关系保留，供未来明确解锁/迁移使用。
- 保留领袖、升级、肉鸽天赋、多存档、中英文界面、米勒地图和全屏 HUD。

### 网页版限制与存档

GitHub Pages 不包含 Node.js 联机服务器；局域网入口不能直接在此站建房。Steam / Epic 与最终写实资源尚未实现。海运由独立物理陆海地形网格处理，不把行政边界当墙或陆桥，详见 [地形寻路](docs/TERRAIN_NAVIGATION.md)。

实际地块 v3 将拜科努尔并入现有卡拉干达州游戏地块，使用独立 mapId 和存档命名空间，需要新建战役。旧 v2、4596原子地图、675州区及更早版本浏览器存档保留，不覆盖、不假装无损迁移。存档只在当前浏览器中保存，不是云存档；重要战役请导出 JSON 备份。localhost 与 github.io 的存档互不共享。

拜科努尔原始行政区只与克孜勒奥尔达州相邻；现有卡拉干达州游戏地块已包含该州，因此本次合并整体连通，不添加虚构邻接。保留全部五个原始行政区及其边界数据，游戏内共用一条生产队列、12容量和一次领土计数。

### 地图来源说明

几何采用 Natural Earth 5.1.1、1:10m Admin1 公共领域数据的完整行政单元，共享边统一简化但不切割行政单元。旧州区仅作初始分组重叠提示，不使用其像素几何。完整 NE 行政单元与 Vic3 州区粒度不兼容，因此分组明确标为近似，不声称精确重建旧 675 块。见 `docs/ADMIN1_OVERLAY_AUDIT.md`。

## 发布与验证

流程固定为 **PR 压缩合并 → main 构建并部署 → 同一已部署 SHA 测试 → 线上验收**。PR 和功能分支不触发 CI，测试不作为合并或部署前门槛。仓库仍要求 PR、仅允许 squash、线性历史、解决讨论并禁止强推/删除 main；分支保护不再要求 `validate` 检查。

`.github/workflows/pages.yml` 由本仓库 `main` push 或手动触发，解析精确当前 HEAD，并要求它是已合并到 main 的 PR 对应的单父提交。其他分支、未合并 PR、非 PR 提交和过时 push 不发布。部署前只安装锁定依赖、类型检查并构建，构建失败不会上线，也不会运行后置测试。

部署成功后上传包含实际发布 SHA、发布网址和运行编号的部署记录，独立的 `acceptance.yml` 才会调用 `ci.yml`，执行同一 SHA 的完整单元、类型/构建和浏览器测试：单元与构建只跑一次，浏览器完整套件分为 3 个独立 runner 的分片，每片单 worker、每个 job 仍限时 20 分钟；分片失败不取消其他分片，单元失败也不阻止浏览器收集证据，全部检查结束后验收实际 HTTPS 网站并归档截图及报告。构建、各浏览器分片与线上验收使用包含 SHA、重试编号及分片编号（如适用）的独立证据包，保留全部截图与测试日志。验收校验发布来源、部署记录、当前 main 与 squash PR，跳过失败、未发布或已过时的事件。CI 本身仍只有 `workflow_call`，验收只监听发布流程，避免触发循环。测试或验收失败会标红，**不会自动回滚已上线内容**。

只有真正的部署 job 使用 `github-pages` 互斥锁，且不取消进行中的部署；启用 `queue: max` 保留最多100个待部署任务，避免较慢的过时构建挤掉最新版本。构建可以并行，旧测试或线上验收不再占用发布锁。独立的 `deployment-priority.yml` 在 main 更新时请求取消较旧验收，不占用发布锁；发布 source 阶段也会检查一次。取消失败只报告警告，不作为部署门槛。首次迁移时，只会取消已经完成全部构建/部署 job、仅剩旧验收的原发布流程，绝不取消仍在构建或部署的任务。独立取消流程会有限等待旧部署结束，再取消其验收；旧 `always()` 验收不响应普通取消时，重新核实发布完成与版本后才强制结束该验收。构建后、获取发布锁后再次检查 main，过时源码不发布。验收先校验实际部署 SHA，线上检查前再次检查新旧版本；取消的验收不会重新启动线上检查。旧验收取消流程有时限，过时 main 或异常会停止处理，不能让它成为新部署的依赖。

手动入口为 Actions → Publish ROUGE to GitHub Pages → Run workflow，仅允许从 main 运行，发布其当前已合并 PR 的精确 HEAD，不等待 CI，也不接受任意旧 ref。需要回滚时通过 revert PR 压缩合并到 main，再走同一部署后测试流程。

## 自动清理已合并分支

`.github/workflows/cleanup-merged-branches.yml` 通过 **GitHub Actions** 实现；没有修改仓库原生 `delete_branch_on_merge` 设置。

合并 PR 后自动预览，并每天预览；自动触发不删除分支。也可手动运行（默认仅预览；明确关闭预览才会实际删除）。只处理本仓库已经实际合并的 PR 源分支。以下分支不会删除：默认/长期/受保护分支，未合并分支，仍被开放 PR 用作源或目标的分支，以及合并后有新提交的分支。

删除前确认合并结果仍在目标或默认分支中，并用 Git 精确 SHA lease 删除，避免并发推送造成误删。没有未核实的批量删除，也不会自动合并任何 PR。执行报告位于 Actions 附件 `merged-branch-cleanup-report`。

## 本地运行

```bash
git clone --branch main https://github.com/RIVERS0FT/rouge.git
cd rouge
npm ci
npm run dev
```

开发服务默认地址为 http://localhost:5187/。需要 Node.js 22.16 或以上。局域网主机执行 `npm run build && npm run lan`。

`main` 是游戏开发主线，已整合线上 v0.5.0 源码。Pages 自动跟随上述已测试的主线合并提交；手机横屏等后续功能尚未纳入。

左键选地块，点击海洋或地图空白取消选中并隐藏左侧地块面板，触摸轻点同样适用；拖动平移，滚轮缩放。拖动、捏合、界面操作及右键/Shift 下令不会取消选中；未选地块时不发送调兵命令。选中己方地块后右键或 Shift 点击地图目标下令，默认派出75%的可用驻军。地块面板只显示属于者、驻军、占领及生产信息，不再显示调兵控件。Esc 打开右上设置，保存入口在设置中；单位升级在右侧，天赋在左下领袖像中。

新地图需要新战役，旧 v0.4.x 存档不覆盖、不迁移。界面简中/英语，缺失地名的地区使用当前语言的未命名标签。地形使用 Natural Earth 官方 Shaded Relief，海洋使用低对比度海面波纹与近景反光，详情见 [地形与海洋](docs/MAP_SURFACES.md)。

### Cosmetic commander identity

The three starting leaders now select a portrait only: Warden home defense, Vanguard movement, and Quartermaster recovery bonuses are removed. Level progression, earned talents and unit upgrades are unchanged. Existing saves retain their leader portraits but resume with the new rules.

The game-creation flag editor includes eight real-country flag presets (China, France, Germany, Italy, Japan, United Kingdom, United States, Switzerland) and a custom three-color editor with solid, horizontal, vertical and cross patterns. Flags are cosmetic and do not select a country, start location, army or map color. They appear in the local HUD and LAN lobby and travel with saved/networked player state. Existing saves without a flag keep the neutral faction emblem. Custom flags accept only enumerated patterns and three six-digit hex colors, never uploads, URLs or executable markup. LAN rules identity changes to prevent mixed gameplay versions.

### 手机操作

手机竖屏与横屏使用适配触控的 HUD：单指拖动地图，双指捏合缩放，鼠标可用滚轮缩放，键盘可用 Home/End 和 ±。底部“地块”和“战况”按钮展开或收起对应面板，便于看图；“天赋”和升级入口仍可直接操作。触摸轻点己方地块后，长按地图目标至少0.55秒再松开下令，默认派出75%的可用驻军。拖动、捏合、取消手势或打开弹窗不会误下令；长按海洋不取消选中。配置、升级和设置弹窗可上下滚动，兼容安全区域与动态视口，不禁用浏览器页面缩放。桌面鼠标操作和游戏规则保持不变。

触屏笔记本无需切换设置：输入模式跟随实际触摸/笔输入、鼠标或键盘事件切换，兼容鼠标事件不会立即覆盖触摸模式。宽屏保持原布局，触摸模式放大触控目标。聚焦地图后可用方向键平移、±缩放；弹窗/菜单打开时地图动作禁用，关闭后恢复，不保留中断的拖动。设备映射统一输出平移、缩放、选择动作，与游戏/界面输入上下文分离。

### 开局、AI与外观配置

新战役按种子确定性分配出生地：每位真人或AI得到两块不重叠、双向陆路可达且各有继续扩张出口的领地；后续出生点尽量远离已分配阵营。旗帜与领袖不影响出生、资源或能力。已有存档不会重新分布。

单人和多人使用数字输入框配置 AI，框内显示当前可输入范围，不再限制4个阵营或4名真人。上限只取决于当前地图能分配的完整出生资源：当前地图按预处理后的实际地块重新计算互不重叠的双区域出生位，单人AI上限为该容量减1，多人AI范围随已加入的真人席位数减少。联机至少2名当前在线真人才能开始，AI及断线席位不计入这一门槛，也不需要等满房间。AI仍预留出生资源，其他玩家加入不会挤走AI；服务端在修改发生时再次校验并发加入、配置和开始。

出生资源上限不代表设备或网络负载保证。大量阵营会增加模拟、路径规划、画面和网络开销，手机与普通局域网建议先从较少人数开始。AI按阵营错峰思考；离线存档与联机状态支持高编号阵营，配色按编号生成。地图数据更新后运行 `npm run prepare:map && node --experimental-strip-types scripts/build-spawn-sites.mjs` 重新生成 `data/spawn-sites.json`；算法在合法双向陆路邻接图上做最大匹配，不使用手写席位上限。详见 [开局容量与性能验证](docs/OPEN_GAME_SETUP.md)。

国旗与玩家领袖形象在单人和多人创建游戏时设置，使用同一原创肖像，并与单位、AI、姓名及必要联机设置集中展示。修改外观后返回原创建窗口，不丢失未完成的其他选项。已有国旗和领袖偏好会自动填入，无需每次重新选择；开始菜单不再展示外观编辑入口。领袖与旗帜偏好保存在当前浏览器，只有这两项，不保存姓名或联网凭证；加载旧战役不覆盖其人物/旗帜。自定义旗帜可拖绘圆、矩形、三角、星形，支持选择删除、撤销与清空。最多24个形状，坐标/尺寸/颜色均严格校验，旧预设和条纹旗帜仍兼容。

连续升级积累多次待选天赋时，选完一项会继续显示下一组；等待权威状态确认后，最后一项完成才关闭窗口。经验与升级规则不变。

地图角落2D/3D/＋/−控件已移除。触屏仍可单指拖动、双指捏合；鼠标拖动与滚轮保持，聚焦地图可用方向键、±，Home回到全图、End聚焦选中地块。

战斗界面的地图来源文字与操作提示叠层已隐藏，地图/来源资料仍保留于说明文档和发布文件；实际输入设备识别及所有地图操作保持不变。

阵营在本帧所有占领统一结算后若领土为0，立即淘汰：残余军队（含海上运输）和未完成占领清除，后续命令被拒绝。失地和新占领同时发生不会误判。玩家看到失败后可观战或返回菜单；多人只淘汰该阵营，其他真人与AI继续，最终胜利规则不变。旧v5存档读取时会按此规则清理零领土残军，原存档文件本身不被自动重写。

选中领土保持原归属填充色，使用金色描边与有限宽度的内边缘柔光标记；柔光与真实陆地三角网求交，不越过海岸或填满孔洞，并沿用2D/3D地形和日期线副本。

### 完整行政区管理初版

选中基础行政单元，在管理面板合并己方相邻管理组，或选择完整基础行政单元拆分。两侧不连通时分别形成连通管理组。军队、占领、训练进度与固定资源预算保留在原子行政单元上，操作使用权威revision拒绝过时联机请求。容量下限是新图平衡规则，不宣称与旧675块总预算完全相同。地理数据与初始组覆盖较大，移动设备性能仍需实际验收。

开始界面在手机与桌面保持同一布局：标题与主菜单靠左，淡出阴影从左侧展开；首页设置可调整语言及打开存档。单位选择固定四列、形象选择固定三列，不按手机断点重排。使用流式尺寸、必要的局部滚动和至少44px的主要触控目标适配较小视口。

### 简洁界面与语言

开始菜单、战役设置、外观、领土管理和战场仅保留操作控件、必要状态及战斗数值。技术选型、地图来源、内部编码/修订号和操作教学不在游戏界面显示；来源与部署信息仍在本说明、docs 和发布文件中。中文与英文分别显示对应标题、系统生成的电脑玩家名称、等级、经验和时间单位，玩家输入的名称与存档名保持原样。兵种属性继续通过悬停、聚焦或轻点查看。手机与桌面沿用相同菜单布局。

国家疆界按实时玩家归属显示，真人与 AI 使用同一规则：不同阵营之间为醒目的深色粗线，同阵营内部不同管理地块之间为低透明度细线，已合并管理组的内部原子边界继续隐藏。每个中立管理地块独立视为一个国家，中立之间也画国家疆界。占领、合并与拆分后即时更新，不改变实际领土、兵力或地理数据；海岸保留独立轮廓，日期线裁切不额外画接缝。国家与选中描边采用屏幕像素宽度，保持手机、缩放和地形视角下的辨识度。

### 首屏与共享资源

首屏只下载菜单、语言、样式与 React 基础代码；菜单绘制后，后台才加载游戏、Three.js 与地图，随后预取模拟 Worker 和领袖图片。准备期间可操作菜单、切换语言及打开设置。提前进入创建游戏或存档会显示可取消的等待窗口，资源就绪后只继续最新选择；失败会保留可用菜单并提示重新加载，不自动开始对局。

行政地图与地形网格从 JS 中分离为按内容哈希命名的 JSON，每种数据在发布目录只保留一份，主线程与 Worker 请求相同 URL，使用 HTTP 缓存复用，消除重复地图下载。每个线程仍独立解析与维护运行时索引，不要求 SharedArrayBuffer 或跨源隔离。Node/LAN 和测试继续读取同一生成数据。源码地图校验、地图身份、存档与联机协议不变。

### 建筑占地与自然驻守

近景小房屋与模拟共用位置、朝向和占地。陆军出生、行进、彼此挤让和读档修复都避开房屋；模型插值也不穿过建筑。地块中心仍是驻守和占领的目标，部队受中心吸引，在建筑边缘与其他单位的碰撞作用下自然散开，不分配环形阵型或固定站位。移动部队会使驻守部队适度让行，避免满员驻地把出征部队堵住。

房屋只在完整占地及最大单位的岸边通行余量都能容纳时绘制，细小海岛或沿岸放不下的房屋不显示，也不生成隐形障碍。原地形流场和海运切换保留，建筑附近使用受原路线与陆地约束的局部绕行。占领半径、容量和训练资源规则不变；联机规则标识更新以拒绝不同模拟版本混用。

### 国家名称

真人玩家的姓名就是国家名称，多人分别保留各自输入的名称。AI 国家在出生地分配完成后，以主出生游戏地块的双语地理名称为根，组合16种国家形式；相同地名先使用不同形式，仍不足时追加序号，命名不限制 AI 数量。不是随机抽取世界其他地方的国家，也不会因为后来征服或失去出生地而改名。名称与出生地一起保存并随多人状态同步，切换中英文只切换 AI 名称的对应语言，不翻译真人姓名。旧版当前地图存档的 AI 名称按原种子重建出生地补齐，未命名源地理数据使用双语“新境”备用名。

国家名称固定在当前最大连通领地的内部地块中心，同一阵营显示一次；占领、丢失、分裂等实际归属变化后重新计算锚点。相机平移、缩放和面板状态不改变锚点，国家文字固定上移24像素与锚点地名分开。日期线两侧按重复地球显示相邻副本，避免换边跳变。国家名与地块名每次地图绘制同步投影；地块名保留原有相机距离小于500时显示的缩放规则。在应显示的缩放范围内，两类文字只有完整边界离开屏幕后才隐藏，局部出屏保留，不考虑面板、其他标签或单位遮挡，不限制名称数量。国家名现有缩放规则不变。两类标签按需复用节点，文字宽度缓存，不接收鼠标或触摸事件。中立势力没有国家名称，仍保留地块地名与中立疆界。

### 地形与海洋美术

陆地叠加 Natural Earth Shaded Relief 3.2.0 灰阶阴影，保留归属色、国家边界和所有标签。海洋使用蓝灰色静态海面与弱波纹，替换海底地形细节；近景 3D 增加随视角变化的轻微反光。波纹在远景和小屏幕自动过滤，避免闪烁。陆地阴影离线重投影至游戏的真实米勒裁剪，日期线副本共用材质，不改变海陆几何、寻路、移动、碰撞、存档或联机规则。

海面无需下载贴图、动画时钟、额外绘制批次或每帧 CPU 更新，沿用暂停/菜单时的停止绘图规则。陆地纹理在地图首帧之后以低优先级异步加载，失败回退为原有纯色可玩地图。手机/受限设备约159 KB，桌面约597 KB，横竖屏切换不重新下载。公共领域来源、SHA-256、复现步骤和能力限制见 [地图表面来源与处理](docs/MAP_SURFACES.md)。

### 随地图视图切换的部队显示

沿用原有缩放视图：远景 2D 战略地图显示阵营着色的 2D 兵种精灵，近景 3D 地形地图显示实体模型。滚轮、触摸捏合或 ± 自动切换；Home 回到战略全图，End 聚焦已选地块。八种陆军各有图形标记，已登船单位统一显示运输船标记；全图缩放时临近单位图标可能重叠，放大即可分辨。

每个可见单位只绘制一次，两种表现共用同一单位 ID、位置、插值、数量和移动/战斗/占领状态，切换不改变存档或游戏规则。2D 图标按屏幕像素限定大小，使用一个批量实例绘制及共享纹理；3D 继续使用批量模型。离开视口的单位不绘制，缓冲区按需增长而不限制模拟人数。图标不接管地块的选择、触摸或下令操作。

部队在两种视图中共用100毫秒快照缓冲，按画面帧插值移动，不再反复追赶新快照。可辨识的移动最高60帧/秒，全图细微移动自适应降低重绘；静止和被弹窗遮住的地图休眠。暂停或网络延迟时停在最后确认的位置，不预测移动；建筑、海岸和登船边界不作穿越插值。实际帧率取决于设备。详见[平滑移动与验证](docs/UNIT_MOVEMENT.md)。

2D部队采用更清晰的浅色边框、深色轮廓、轻微立体底板与加粗兵种标记。共享高分辨率图集逐级缩小并隔离各兵种边缘，透明边缘保留连续覆盖率，减少缩放和移动中的锯齿、闪烁与串图；阵营着色、单位数量和单次批量绘制保持不变。

### 国家地图名称

国家名称沿国土内部的单弧线排列，每个名字仅使用一个控制点的二次贝塞尔曲线，只有一个弯折方向。优先选取最大的连通国土，避开湖泊、海湾及离岛间的海面；国土过于曲折时选择较短的内部弧线。行政区之间的内部边界不影响可用空间。使用真实国界的内部距离计算整段文字的安全范围，完整字形、重音符号和描边均保留余量；字号与字距随可用路径调整，空间不足以显示至少 10 像素文字时，放大地图后才显示。面积重心仍用于几何统计，但不再强制文字落在可能位于海上的重心位置。

国名字样参考维多利亚 3 官方实机截图的细衬线墨字和疏朗字距，使用系统字体与 SVG textPath，逐字沿曲线转向。路径按国土归属缓存，征服或失地后仅重新计算受影响国家；平移、缩放、语言和 HUD 操作只更新投影或文字排版。跨日期线的国土统一展开，避免国名在两端之间跳动。省名保留原有近景显示范围。

国旗采用轻微弯曲的布面、明暗褶皱和缓慢飘扬动效，应用于阵营栏、外观预览和联机大厅。系统设置减少动态效果时保留静态布面。自定义旗帜绘图画布保持平面坐标，预设与自绘内容仍按原格式存档和联机同步。视觉参考：[Victoria 3 官方截图](https://store.steampowered.com/app/529340/Victoria_3/)。

左下角领袖画像显示玩家名称，左上角显示当前等级；手机在头像姓名条右侧显示等级，长姓名省略显示但保留完整标题。点击或键盘激活整张画像仍打开天赋，待选天赋用边框与无障碍标签提示。经验和天赋详情仍在原有面板，单人存档与多人身份规则不变。

海面采用深青色、柔和的不规则细纹与淡经纬网，远景保持低对比，近景保留轻微反光。真实海岸向海面投下柔和渐淡的阴影，突出大陆和岛屿的立体感；密集海岸的阴影浓度统一封顶，保持陆地原色。桌面战地简报固定在右下角，较长内容可独立滚动；手机仍通过“战况”入口查看。
