# 万兵实战性能复测

测试使用已保存的真实对局，从第 20,638 tick、10,065 个单位、1,686 支军队开始。人类席位已经出局，因此用游戏内观战模式回放。3D 镜头固定在伊比利亚半岛的行军密集区，2D 镜头固定在欧洲战略地图。两个镜头都在移动和缩放。合成满图与纯地图是单独的对照场景。

## 实战结果

测试机为 Core i7-10700、Intel UHD 630、Chromium 153，使用硬件 WebGL。表中的 P95 表示 95% 的实际绘制帧间隔不超过该值。3D 逐秒采样覆盖了 192 至 208 个可见单位，2D 的部队模型数和插值轨迹数均为零。六个窗口内，从源状态计算的应显示单位数均与渲染列表相符，包括每支登船编队对应的一艘船。

| 视图与轮次 | 平均 FPS | 模拟 tick/s | P95 帧间隔（毫秒） | 最长帧间隔（毫秒） |
|---|---:|---:|---:|---:|
| 2D 第一轮 | 39.52 | 11.53 | 103.8 | 298.5 |
| 2D 第二轮 | 20.40 | 5.10 | 152.9 | 749.7 |
| 2D 第三轮 | 24.29 | 4.70 | 146.0 | 659.8 |
| 3D 第一轮 | 13.38 | 12.88 | 90.2 | 326.6 |
| 3D 第二轮 | 13.55 | 13.27 | 90.1 | 243.2 |
| 3D 第三轮 | 10.83 | 14.29 | 118.4 | 208.5 |

同一测量设置下，改动前的 2D 为 12.66 FPS、11.86 tick/s，3D 为 11.89 FPS、12.46 tick/s。改后三轮中位数分别为 24.29 FPS、5.10 tick/s，以及 13.38 FPS、13.27 tick/s。2D 帧率达到原来的 1.92 倍，3D 中位帧率提高约 12.5%，第三轮低于原版单次基线。各版本按墙钟预热，所以正式窗口从不同的模拟 tick 开始。

实战帧率和模拟时钟均未达标。2D 运行窗口中的平均绘帧 CPU 时间已降到 5.8–9.7 毫秒，但最慢的一批帧仍有明显停顿。3D 密集视角每帧平均提交约 130 万个三角形。单独测量暂停模拟的 3D 纯地图，平均为 96.85 FPS，P95 帧间隔为 20.7 毫秒，达到纯地图 60 FPS 目标。

关闭游戏渲染，仅运行正常模拟 Worker 和客户端快照解码，预热 60 秒后实测 60.17 秒，推进 1,092 步，即 **18.15 tick/s**。平均模拟步耗时 50.87 毫秒，P95 为 72.80 毫秒，平均快照解码耗时 3.09 毫秒。窗口结束时已有 11,760 个单位。即使单独运行模拟，这一段后期战局也已超过每步 50 毫秒的预算。

确定性检查从同一存档逐步运行两个引擎，预热 5 步并测量 400 步。405 次完整游戏状态（含随机数状态）及碰撞报告均逐步相等。Node 同步单步均耗时从 100.13 降至 84.77 毫秒，减少 15.3%。

六次实战测试中，有 4 次在读回时已有第 21,838 tick 的定时存档。其余窗口在结束时尚未推进到该存档边界。另用同一份初始状态单测存档，读回的完整状态一致。原版保存耗时 143 毫秒，主线程出现一次 119 毫秒的长任务。改后冷启动 Worker 的保存总时间为 2.39 秒，该次操作期间观测到的主线程长任务数为零。退出并存档仍需等待写入完成。

单独开启 GPU 查询后，在相同 3D 密集视角的 12 秒诊断窗口中，主场景 GPU 工作平均 64.15 毫秒，P95 为 92.16 毫秒。仅这一项就高于 30 FPS 的 33.33 毫秒帧预算；攻击箭头的 CPU 投影另占每帧 6.24 毫秒。诊断窗口专用于定位耗时。上表六轮正式测量均关闭 GPU 查询。

**活跃玩家的合成对照。** 初始为 10,000 个单位和 333 支军队。第一版始终扩展缓存边界，12 秒短测的 2D 帧率从 4.31 降到 3.63 FPS，3D 从 12.06 升到 12.30 FPS。对 2D 使用相同镜头、60 秒预热加 60 秒实测，基线为 5.90 FPS，固定扩边为 4.89，仅使用视口原生纹理为 5.87。最终实现根据实测更新间隔决定是否扩边，测得 **4.22 FPS**，相较基线低 28.5%；模拟从 **17.55 变为 7.54 tick/s**。各配置各测一个长窗口。

同一台机器在不同时间的基线也出现波动。最后一次使用原版重新测量，真实 2D 为 6.48 FPS、5.82 tick/s，合成 2D 为 3.80 FPS、7.44 tick/s。合成正式窗口起始 tick 为 704（晚测原版）与 698（最终版本），终点分别为 1152 与 1150。最终合成帧率位于早晚两次基线之间。主机负载未锁定，单次运行之间的差异不能全部归因于代码。

## 实现

- 陆地行军、登船与登陆沿用原有候选顺序。编队的占地索引随位置、朝向、成员数和海陆状态更新。在同一地点被静态地形挡住的成员可复用上次移动结果。部署前先剔除所有候选出发点都碰不到的编队。
- 平面地图在地面坐标中保存箭头的轮廓与描边。镜头移动时共享一次坐标变换，画面仍在已有纹理覆盖范围和清晰度内时直接复用。更新间隔持续变长时按视口原生尺寸绘制，更新恢复频繁时再扩展缓存边界。靠近地平线的透视箭头继续裁剪。军牌保留选择优先级和围城时的堆叠顺序。
- 3D 步兵的 41 个姿态预先计算进 GPU 纹理。每个可见实体仍使用原模型的 6,230 个三角形、原动画帧和材质。船只与加载阶段的模型仅上传实际使用的实例矩阵。
- 自动存档在独立 Worker 中校验和编码，随后按调用顺序提交至 IndexedDB。读档、手动存档和删除共享同一顺序。编码仍使用游戏原有的存档格式。

## 回归验证

完整 Node 套件通过 629/629。针对本次改动的浏览器套件通过 18/18，覆盖镜头移动与接缝、箭头锚点与裁剪、围城军牌、拖曳派遣、驻军显示、存档顺序，以及逐顶点比较全部 41 个步兵姿态。箭头锚点测试发现单点与轮廓的浮点计算顺序相差约 10⁻¹³ 像素，两者已统一使用同一变换。三个 3D 正式窗口在这个精度修正之前完成，三个 2D 正式窗口使用修正后的自适应缓存版本。测量期间工作区另有战斗徽标强度条等改动，性能数据取自本轮优化的固定源版本；最终生产构建另外验证了合并这些工作区改动的源码副本，最终参数的 7 项地图与箭头浏览器回归全部通过。

从当前源码的隔离副本运行 `npm run build` 成功，包含地图生成、模拟内核准备、TypeScript 和 Vite 生产打包。另从生产预览实际写入手动存档和自动存档、刷新页面并加载成功。测试使用独立的浏览器上下文。

## 如何复测

在项目根目录启动开发服务器，指定本机 Chromium 路径。下列命令会从同一存档独立启动六次 Chromium，每次以 1× 速度预热 60 秒、测量 60 秒，保存实测帧间隔、游戏 tick、单位数、自动存档 tick 和运行截图。

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = '本机 Chromium 可执行文件的绝对路径'
node scripts/profile-live-campaign.mjs --snapshot=.cache/perf-campaign-nov18/real.json --url=http://127.0.0.1:5187 --flatFocus=122.074327145583,-549.508845705757 --nearFocus=-82.3046755766882,-412.427772597611
```

桌面视口为 1510 × 1090，DPR 为 1.25。验收取实际绘制帧数除以墙钟秒数，每个窗口分别检查 2D 60 FPS 或 3D 30 FPS，以及 1× 的 20 tick/s。客户端每两步发布一次状态，允许两个 tick 的边界误差。用原始工程副本的同一存档与相机测基线，基线包含本轮开始时工作区里已有的修改。

逐步等价性可以独立验证。参数 `--reference` 指向基线工程的引擎入口，该工程需要自身的地图和模拟内核。

```powershell
node --experimental-strip-types scripts/profile-simulation-pair.mjs --snapshot=.cache/perf-campaign-nov18/real.json --reference=.cache/perf-campaign-nov18/base/src/game/engine.ts --steps=400
```
