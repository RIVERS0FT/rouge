### 本轮实现与画质验证

- 背景每次只绘制一个 512×512 内容块，另带两像素边缘。直接以 viewport/scissor
  写入后备纹理，避免纹理复制引起的同步等待；整张完成后再交换前后纹理。
- 旧缓存只在覆盖视野且像素密度足够时显示。快速放大或缩小超出条件时，直接以
  完整分辨率绘制当前地图；不显示放大的低清占位图。大幅连续手势的直接绘制成本
  仍可能较高，本次采样覆盖的是脚本中规定的连续往返手势。
- 海岸阴影按块的实际 viewport 偏移取样，国界线宽按 CSS 像素校准。整块/分块
  逐像素对照涵盖海岸、交叉边界、边缘接缝；每通道差异不超过 2/255。
  构建过程中前台像素保持不变；中途内容变化后会继续刷新到最新版本。
- 陆地、海岸线、国家和管理边界按完整三角形或线段剔除，保留所有原始端点、
  归属颜色和占领属性。静态地图与世界重复副本不再逐帧重算矩阵。
- 国名先剔除视野外的整段曲线，再投影实际可见部分；复用字体条目与 DOM 节点。
  缓存相机仅在新任务开始时复制；LOD 仅在可见图块范围变化时重排请求。
- 快速离开后重新进入同一图块时，取消的请求会正确重试，不被永久当成资源失败。
- 部队插值活动查询只遍历可见 ID，整队查询使用 values 迭代，避免每帧为各部队
  创建键值数组；原有插值位置和结束时机通过回归验证。

此视口的双颜色缓存与共享深度约占 **169.5 MiB**，原单颜色/深度缓存约 **113.0 MiB**。
这是本轮降低重绘尖峰的显存代价；没有降低 DPR、底图 LOD 或国名字形精度。

### 剩余尖峰与下一步

另开 GPU 计时采样，近距拖动/缩放的单块背景绘制平均开销分别折算为
**908.8 / 847.0 FPS**。这些数值仅说明单个 GPU 阶段的开销，实际帧率仍按上表计算。
[GPU 分段原始结果](performance/2026-11-14-map-incremental-gpu.json)记录了实际 scissor，
可核对任务只覆盖单块，而不是重新绘制整张 4530×3270 的纹理。

浏览器跟踪发现主线程垃圾回收仍会叠加渲染开销；最终记录中也存在浏览器 rAF
整体延后的情况。现有证据不足以把所有长帧归于同一个原因。下一轮应对最差帧
同步记录主线程、GPU 和合成线程，再分别验证减小主线程静态对象规模、减少地块牌
DOM 更新、将地图绘制迁入 OffscreenCanvas Worker 等方向，仍以这六组手势的最慢
单帧不低于 60 FPS 验收，不能仅凭平均值通过。

历史记录只隐藏绘制模型，仍残留部队插值轨迹扫描；本轮已排除这部分开销。
历史样本也启用了 GPU 查询，本轮主表使用轻采样，GPU 归因另测，因此两表不应
作为完全等价的 A/B 对照来精确计算每项改动的收益。

### 点击选中反馈：实时叠加层

选中轮廓与内侧光晕从底图缓存移到独立的实时地图层，世界重复副本同步更新。
选择、取消选择及光晕后台计算完成均直接触发下一次绘制，不再改变底图版本，
也不受静止地图的 30 FPS 调度限制。缓存生成时隐藏这些叠加层，避免留下旧高亮。

独立 Chromium、1440×960、DPR 1.25、暂停的国名测试夹具中，实际点击同一德国地块，
修改前缓存首次切换在第 **54** 个绘制帧；修改后边框在第 **1** 帧上屏、光晕在第 **2**
帧上屏，全程复用原缓存。这里统计响应经过的绘制帧数，不是持续帧率或所有地块的
光晕计算耗时保证；复杂海岸仍由后台任务计算。该专项未重测上表的六组性能数据。

相关核心回归 **26 项**、原生 GPU 浏览器回归 **5 项**通过。新增像素回归确认取消选择后
没有残留高亮，并覆盖缓存刷新、快速切换、世界重复副本及原有 3 CSS px 选中线宽。

## 掉帧尖峰归因

把 GPU 查询拆成屏幕绘制与离屏背景重绘，再对近距手势各采样十二秒：
拖动平均 121.9 FPS，缩放平均 126.2 FPS；最慢单帧等效分别为 13.0 / 14.3 FPS。
普通屏幕绘制的 GPU 开销等效约 334 / 337 FPS；背景重绘开销等效约
13.8 / 14.2 FPS。原始结果包含时间戳，可对齐长帧与 GPU 任务：
[2026-11-14-map-spikes.json](performance/2026-11-14-map-spikes.json)。

当前离屏缓存采用 1.6 倍视野范围和 1.5 倍像素密度，在此设备生成
4530×3270 的缓存，像素数约为实际绘制缓冲的 5.76 倍。复用缓存时成本很低；
新图块上传、覆盖范围不足或放大超过现有缓存精度时，需要整张重绘。
这项 GPU 任务造成明显长帧。整段采样没有超过浏览器长任务阈值的主线程任务，
但个别字体/布局调用仍可与 GPU 等待叠加。

本轮已实施分帧背景绘制并验证接缝、颜色、视野覆盖与内容更新，结果见报告前部。
平均 FPS 达标与最慢单帧达标仍需分别验收。

## 复现

```powershell
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH = '本机原生 Chromium 的绝对路径'
node --experimental-strip-types scripts/profile-frame-rate.mjs `
  --snapshot=.cache/live-state.json --mapOnly --noGpu `
  --views=global,flat900,flat450 --actions=pan,zoom --duration=12000 `
  --width=1510 --height=1090 --dpr=1.25 --output=.cache/map-only.json
```

`--snapshot` 使用本地捕获的 `{state,canvas}`；存档未随报告发布。
也可以不传该参数，使用可重复生成的合成测试世界。`--mapOnly` 暂停模拟、
清空测试浏览器中的部队绘制列表和插值记录，不改游戏源状态；与 `--running` 互斥。
`--noGpu` 关闭逐次 GPU 查询以减小采样扰动；省略该参数可复现 GPU 分段归因。
GPU 原始查询和机器可读结果保留原始时间单位，控制台及面向用户的摘要统一换算 FPS。
