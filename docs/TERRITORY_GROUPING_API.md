# Administrative territory grouping (isolated integration contract)

The pure partition model is integrated through territoryRuntime/territoryEconomy into authoritative commands, saves, LAN deltas and management boundaries. It does not change the independent physical terrain routing mesh.

- `TerritoryTopology.mapId` must match the new pinned Natural Earth build. Stable atoms are complete Admin1 `adm1_code` strings (e.g. `CHN-1808`), not runtime array indices. Set `playable:false` on out-of-viewport atoms. Neighbors must be symmetric, real positive-length shared borders; this module never infers connectivity from centers, coastlines, corner touches or sea routes.
- Adapt generated `{id,atomIds,legacyHint,reason}` groups via `createTerritoryGrouping(topology, generated.initialGroups.map(g => g.atomIds))`. IDs are `group:<smallest atom ID>` and deterministic across clients. Every atom must appear exactly once in one connected group.
- Maintain immutable atomic accounts: owner, troops, accumulated production work, production rate and capacity. Unit positions/HP/orders, queues and per-kind progress remain authoritative at atomic level. Aggregated totals are display/accounting values, **not** a replacement training queue or permission to spend one atom's progress on another. This prevents merge/split from spawning units, restarting queues or multiplying capacity.
- `applyTerritoryGrouping(topology, state, ledger, authenticatedActor, unknownCommand)` returns a new partition only on success. Commands include exact `mapId` and `expectedRevision`. Never accept actor/ledger from request fields. Consume the current state and increment revision atomically in the same authoritative event loop. Failure does not mutate state or ledger.
- Merge selects existing whole groups, all fully owned by actor, and requires connected union. Split selects complete atoms within one fully owned group. Selected and remaining sides each become their connected components. Empty/duplicate/unknown/half-atom selections reject; selecting the entire group returns `noChange` (not an implicit dissolve).
- `reconcileTerritoryOwners` runs after all captures in the simulation frame, before accepting later grouping commands. Mixed-owner groups split into homogeneous connected components; revision changes only if partition changes. Ownership must be rechecked even if revision is unchanged. The caller separately determines whether the faction is still active.
- Broadcast/save the versioned partition and atom-to-group index together with atom state. Validate the complete partition on reads; never silently repair malformed external partitions.
- **New map, incompatible old saves.** A different `mapId` fails validation/commands. This module offers no geometric migration. Integration must use separate storage namespace, preserve legacy save files, and explain incompatibility rather than overwriting or pretending a lossless conversion.

Resources are conserved because neither operation writes the atomic ledger. `totals` uses stable atom order to avoid merge-order floating-point differences. Group-level totals can be queried with `territoryTotals(topology, ledger, group.atoms)`; reservations and individual troop/queue references must likewise remain attached to atoms in engine integration.

## Fixed initial economy

Each initial playable group receives capacity max(12, playable atom count), distributed deterministically with at least one slot per atom, and one total production rate. Income is proportional to the same immutable production allocation. This is a new-map balance rule, not equality with the former 675-group budget. The runtime dataset totals 16,830 capacity and 1,323 production rate. Merge, split and capture never recompute these atomic budgets or manufacture soldiers/progress. Starts select two whole groups of at most 12 atoms, giving each human/AI 10 troops, 24 capacity, production rate 2 and equal income despite different atom counts. The generated data has 1327 initial groups including four outside the viewport (1323 visible groups).
