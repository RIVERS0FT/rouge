# 世界米勒圆柱地图 · v0.3

## 本次实现

- 以 Natural Earth `ne_10m_admin_1_states_provinces` 替换 32 个架空 Voronoi 地块；固定源仓库提交 `f1890d9f152c896d250a77557a5751a93d494776`（v5.1.2 标签），而非随时变化的 master。
- 4,596 个源行政区要素，4,594 个可玩要素；两个南极要素只显示，不生产、占领或计入胜利分母。
- 真实海岸线、行政区、名称、MultiPolygon 离岛和内环；中英名称由数据提供，缺译名时回退原名；无名源要素回退国家名/稳定编码。
- 标准球面米勒圆柱：中央经线 0°，X 向东、Z 向南，每经度 10 游戏单位。纬度范围 ±90°；两极有限，不沿用墨卡托的 ±85.051° 裁剪。不是等距矩形、保角或等面积投影，也不声称完全复现《维多利亚3》的投影参数。
- 北朝上的全球 2D 视角；可连续缩放至倾斜的 3D 地形视角。国家底色是中立地域区分，不表示玩家已拥有整个国家。
- 行政区使用带孔三角剖分，每个离岛单独绘制。陆地与边界批绘制，最多 48 个动态标签。
- 按行政区中文名、英文名、英文国家名或稳定编码搜索，选择后聚焦。2D 按钮返回全球，3D 聚焦当前选区。
- 空间索引服务地图拾取；射线迭代匹配显示高度，不再把每次点击交给数十万三角形逐一碰撞。
- 陆地邻接从源数据的共享边段提取，角点接触不算相邻。双省份局部共享流场取代全球粗栅格。
- 初始化只在欧洲大陆及其前沿生成兵团，不在 4,596 个行政区各自生成单位。所有非南极行政区可被选择；纯陆路命令依地理连通性验证。
- 生产、战斗、占领、升级、天赋、存档和 LAN 仍使用同一模拟。规则增加动态行政区数量与稳定地图版本。

## 兼容与边界

1. 新战局 `map=earth-admin1-miller-v1, version=3`。旧架空地图及墨卡托地图存档不迁移、不覆盖；新存档前缀 `rouge.save.earth.miller.v1.`。联机 API 要求 `X-Rouge-Map` 与主机地图一致，初始及增量快照也检查地图和版本；旧客户端不得用不同坐标解释同一状态。
2. Natural Earth 的 Admin-1 图层并非每个国家都采用同一行政层级，例如包含部分国家的二级行政区；本次保留来源并称“行政区”，不声称 4,596 个要素均已归一为省级。发布前必须按市场核验行政层级、译名和边界表达。
3. 源数据沿用 Natural Earth 的边界表达，不代表对争议地区归属作判断，也不保证反映当前最新行政变更。
4. 近景高度仍为程序化表现，**未接入真实 DEM 高程**；城镇/士兵为占位资源。真实的是平面地理与边界，不是卫星级地貌或最终写实美术。
5. 陆军暂只导航行政区主陆块。离岛、飞地、狭窄到低于局部网格分辨率的通道可能不可抵达；不会通过自动连海边、瞬移或涂实孔洞伪造通行。尚无海运、航线或环绕世界的跨反经线行军。
6. 行军速度与武器射程仍是抽象游戏单位，未全面转换为真实公里/小时或按纬度校正；以 `groundMetric(z)` 分别提供东西向和南北向尺度供后续使用，不能继续使用墨卡托单一 cos(latitude) 系数。经济也不按投影面积加成。
7. 开始菜单先加载最小界面资源，显示后才后台加载游戏代码与地图。行政区和地形 JSON 各生成一份带内容哈希的资源，主线程与 ES 模块 Worker 并行请求相同 URL，并复用 HTTP 缓存，不再把两份大数据重复打入 JavaScript。下载失败会保留菜单并提供重新加载入口。主线程与 Worker 仍各自解析并建立运行时索引，不共享内存；也没有按地区分块。局域网连接/重连发完整动态快照，后续只发行政区变化和动态军队/玩家状态。全球级性能仍需实际设备验证。
8. 单省生产上限、全军 90 编制和全局 360 兵团仍是原型限制；未宣称实现原设计的几千兵团性能目标。Steam/EOS 仍未接入。

## 米勒公式与数据约定

令 λ、φ 为弧度经度与纬度，S = 10 × 180 / π 为游戏单位比例：

```text
x = S × λ
z = -S × 1.25 × ln(tan(π/4 + 0.4 × φ))
φ = atan(sinh(-0.8 × z / S)) / 0.8
λ = x / S
```

实现采用等价的 `asinh(tan(0.8φ)) / 0.8`，赤道精确为零；正向裁剪非法范围的纬度至 ±90°，反向将超出有限图幅的 Z 裁剪至极点。NaN/Infinity 拒绝，反经线两侧维持各自端点，不自动创建跨边界行军连接。

世界边界 X = ±1800，Z ≈ ±1319.75817213。两轴使用同一比例，不额外拉伸画面；镜头根据全图边界、视口宽高比及 20% HUD 留白计算距离。近景只改变相机倾角与视觉高度，不换地理投影。

`src/generated/world.json` 是经度/纬度数据，格式 2 使用 `coordinateSystem=OGC:CRS84` 表示 lon/lat 顺序，不存储显示投影。旧格式元数据可离线规范化，4,596 个行政区的几何、代码、排序与邻接均保持原样。地图的运行时投影唯一来源为 `src/game/geo.ts` 的 `PROJECTION_ID`；Canvas 和地图元数据不再标记 EPSG:3857。

纬度 φ 处，从投影微分到赤道等效地面单位的系数为东西向 `cos(φ)`，南北向 `cos(0.8φ)`。该接口仅供未来真实尺度功能使用，目前不改变单位平衡参数。
